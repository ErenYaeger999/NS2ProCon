# 震动与实验性触觉增强

0.8.0 默认包含通用游戏震动，可选原生触觉增强支持按需安装和自动管理，详见[增强组件安装说明](enhancement-setup.md)。下方手动后端步骤保留给已有兼容环境的高级用户。

## 通用游戏震动

默认使用 Xbox 360 / XInput 输出和现有 ViGEmBus，无需新增驱动、Python 或音频组件。到「设置与诊断 → 手柄震动」开启反馈并调整强度；到「手柄测试 → 震动测试」体验低频、高频、左右侧、轻点和短脉冲。每次测试自动结束，也可点「立即停止」。测试期间丢弃游戏震动，避免混入正在测试的效果；结束后等待游戏的新反馈。

游戏低／高频强度分别转换为两个 LRA 的低／高频分量，不能把 XInput 的两个电机直接理解为空间左右声道。内部帧保留独立左右频率与振幅，供测试及增强来源使用。强度默认 65%，BLE 振幅字段使用 500/1023 的软件上限；该上限不代表任天堂公布的连续工作安全额定值。频率参数为协议代码，尚未按实物测量标定为物理 Hz。

只有一个异步写入泵，最多一个在途写入；最短间隔 15 ms，慢适配器按实际写入耗时自然降低速率，状态更新合并而不积压。零反馈和断开有停止屏障。恒定效果定期刷新，不因游戏没有重复回调而过期。输入中断、系统休眠、断开与退出会清除效果；恢复后不会重放旧效果。写入错误会停用本次连接的震动并保留输入，诊断日志记录反馈次数、合并次数、写入次数和最长写入耗时。

连接仍使用 SYNC 临时 BLE 会话。新增写入仅用于瞬时震动，不发送主机配对、Flash 写入、固件或唤醒命令。回到 NS2 时，先断开 PC 连接，再按 HOME。

## 可选 DualSense 实验模式

路径为：游戏原生 DualSense 触觉 → 虚拟 USB 音频端点 → 外部 VIIPER V5 → 本应用转换 → NS2 Pro BLE。它只消费后端专用的后置触觉采样，不录制系统、音乐、对白或前置扬声器声道。

要求：

- 手动模式需先运行提供 `dualsensecombinedaudioduplexv5` 和 VPCM V5 的 [hbashton/VIIPER](https://github.com/hbashton/VIIPER) 版本。普通旧版、仅 HID 的虚拟 DualSense 不满足触觉音频要求。自动管理模式由本应用检查和启动固定版本。
- 后端需要兼容的官方签名 [usbip-win2](https://github.com/vadimgrn/usbip-win2/releases) 驱动。自动管理在用户点击安装后才下载缺少的组件并调用官方安装器；检测、切换方式和修改端口都不触发安装，不修改测试签名或 Secure Boot 设置。
- 后端本机 API 默认端口 3242；可在实验选项里修改。仅允许 IPv4 loopback，须允许本机未认证 API 连接；不会读取或记录后端密码。

手动模式先启动后端，在「设置与诊断 → 游戏模式」选择增强，并在高级选项关闭「自动管理增强后端（推荐）」、设置端口并检测；自动管理无需另开后端。环境就绪后连接手柄，最后启动游戏。切换模式前先断开，同一会话只创建一种虚拟游戏设备。不要让其他手柄桥接软件同时接管实物手柄。保持系统主扬声器为原来的音箱／耳机；本应用不播放虚拟手柄扬声器、不提供麦克风或体感输入。

原生触觉需要 PC 版本本身提供；部分游戏须关闭该游戏的 Steam Input 转换。单凭同名 NS2 版本支持 HD 震动，无法恢复 Steam 版本没有输出的效果。后端仍会转发普通 DualSense 双电机反馈作为同一模式内的回退；游戏不识别 DualSense 时，需退出游戏、改回 Xbox 模式并重新连接，不能根据暂时没震动自动换设备。

实现严格检查 V5 版本、长度、CRC 和帧序号，处理分段 TCP 数据。使用 0x83 原子媒体帧中的 64 字节、3 kHz 有符号 8 位立体触觉数据，忽略可能重复发布的 0x84 实时副本。前置扬声器采样不参与转换。每侧通过短窗频带分析近似为低／高频参数；断流约 83 ms 后取消原生采样效果，普通游戏恒定震动不受此采样租期限制。此路径不是无损 PCM 透传，也不复现机械自适应扳机阻力。

增强模式中的普通震动以 0x81 原始 USB 输出指令为准，检查普通或改进型震动启用标记；取消启用也按停止处理。0x83 媒体帧中的双电机字段是缓存快照，不用于重新启动旧效果。原生采样的有效期即使在蓝牙写入期间结束，发送器也会在等待新反馈前补发归零。没有逐段播放的效果队列，只保留最新状态与停止屏障。

### 许可与来源

本项目新增代码自行实现，保持 MIT；协议布局交叉核对于 [Nintendo BLE 研究](https://github.com/ndeadly/switch2_controller_research/blob/master/bluetooth_interface.md)、[BlueRetro](https://github.com/darthcloud/BlueRetro/blob/master/main/bluetooth/hidp/sw2.h)、[SDL](https://github.com/libsdl-org/SDL/blob/main/src/joystick/hidapi/SDL_hidapi_switch2.c) 和 [VIIPER V5 文档](https://github.com/hbashton/VIIPER/blob/main/docs/devices/dualsense.md)。没有将 GPL 项目的转换器、生成客户端或二进制复制进本仓库。外部 VIIPER 保留上游 GPL 授权；当前发行流程不分发它，将来若捆绑需另行核对分发义务与兼容性，不能把分进程视为自动免除许可义务。

DualSense 普通／改进型震动的启用标记及取消启用的停止方式另核对于 [SDL PS5 后端](https://github.com/libsdl-org/SDL/blob/main/src/joystick/hidapi/SDL_hidapi_ps5.c)；本应用只解析公开协议字段，没有移植上游实现。

## 验证

自动检查覆盖 BLE 编码、限幅、弱反馈、发送合并、停止、持续刷新、输入恢复、设置迁移、V5 CRC／序号／长度、立体频带转换，以及本机模拟服务器的输入与反馈生命周期。模拟服务器检查不等同于真实虚拟音频驱动或游戏通过。

可选的真实 ViGEm / XInput 回调检查（只驱动测试程序自己创建的虚拟设备，不连接实物手柄）：

```powershell
./.tools/dotnet/dotnet.exe run --project tests/NS2Pro.Core.Tests -c Release -r win-x64 -- --probe-feedback
```

### 本机实测 · 2026-10-17

- 160 项自动检查通过；实际 WinUI 窗口、五个页面和随包运行环境加载通过。
- ViGEm 原生集成检查收到 XInput 两路、微弱值和零反馈；通过输入签名识别测试程序自己创建的设备，避免向其他手柄发送震动。
- 用户确认测试页六种效果、左右区分、立即停止及震动同时操作按键／摇杆均正常；旁边 NS2 保持休眠。
- 独立 XInput 测试源向本应用的 Xbox 输出发送低频、高频、混合持续、微弱及三个短脉冲。用户确认持续段保持、脉冲和停止正常，并确认断开后 HOME 可直接回 NS2，无需重新配对。
- 本次会话日志记录 20 次游戏反馈、541 次震动写入，最慢写入 15.6 ms，输入平均 66.5 Hz。正常关闭测试版后完成最终停止、释放蓝牙与虚拟设备；XInput 枚举不再存在该设备。这些是当前链路的记录，不代表所有适配器的延迟上限。

0.8.0 另通过 224 项自动检查，以及本机真实 VIIPER 启动、虚拟 DualSense 和同设备容器音频端点验证。已验证外部后端不可用后切回自动管理，能直接复用已安装组件，不下载、不重装、不要求重启；停止后清除旧就绪状态。本机也有增强模式下实物 BLE 输入和震动会话记录。

0.8.2 增加回归检查，先复现了两处停止问题：蓝牙写入跨过原生采样有效期时漏发停止，以及取消 DualSense 震动启用后仍重复使用后端缓存值。修复后 227 项自动检查通过（带实际增强组件归档检查时为 230 项），覆盖真实 TCP 分段反馈、媒体快照不重播、普通／改进型启停、选择音频触觉及慢写入后的最终归零；通用恒定震动和最新状态合并检查继续通过。用户在《空之轨迹2》中复测，确认增强模式震动可以正常停止；此结论不代表已验证其原生触觉相较通用模式的提升。

本次游戏测试还发现增强连接后，Windows 的默认音频输入／输出可能切换到 DualSense。当前需要在系统声音设置中切回原扬声器／耳机和麦克风，建议进游戏前完成；已经启动的游戏必要时重进。默认音频设备的保留与恢复列为 TODO，尚未实现；具体操作见 [README](../README.md#可选原生触觉增强)。

### 按键提示与增强兼容性 · 初步调研

增强模式在本项目中创建的是 `dualsensecombinedaudioduplexv5`，游戏会看到 DualSense HID 和触觉音频端点；[VIIPER 的固定版本文档](https://github.com/hbashton/VIIPER/blob/v0.1.9-rc4.6.6/docs/devices/dualsense.md)与 [DS4Windows 的使用说明](https://github.com/hbashton/DS4Windows#keep-the-detail-lose-the-cable)均将原生游戏触觉建立在 DualSense 输出上。[Steamworks 文档](https://partner.steamgames.com/doc/features/steam_controller/steam_input_gamepad_emulation_bestpractices)说明按键图标由游戏依据输入来源或手柄类型选择。因此，当前增强模式可能使游戏显示 PS 按键图标，本应用的映射预设不能修改游戏的图标资源或显示策略。

若游戏提供独立的提示样式设置，可尝试保持 DualSense 输出、只选 Xbox 图标；是否与触觉开关独立，须逐游戏验证。简单改成 Xbox 360 输出只能接收 [XInput 的低／高频双电机强度](https://learn.microsoft.com/en-us/windows/win32/api/xinput/ns-xinput-xinput_vibration)，不能保留这条 DualSense 原生触觉通道。VIIPER 虽提供音频 sidecar，但仅有音频端点不能保证游戏会为另一只 Xbox 设备生成 DualSense 专用触觉；同时呈现两种手柄还需解决游戏选择、反馈归属和重复输入问题。

初步调研未找到可直接接入、普遍保留原生触觉并强制 Xbox 图标的方案。后续可优先记录各游戏自带图标选项，再评估逐游戏适配；不把 Steam Input 转换或普通声音生成震动等同于保留原生触觉。本次仅记录限制与 TODO，程序行为未改动。

以上不能替代不同蓝牙适配器的兼容性测试。仍待验证：真实游戏原生触觉的提升、与 NS2 的震感对照、Windows 10 适配器及真实系统休眠恢复。环境通过和普通震动正常，不等于具体游戏的原生触觉效果已验证。
