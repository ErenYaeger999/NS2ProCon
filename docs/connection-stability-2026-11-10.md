# 连接稳定性修复与验证

日期：2026-11-10。问题基线：v0.9.0，提交 `8564433a00e638748905f29807fa9c361f763f3a`。本轮代码修复随 v0.9.1 发布，实物复测状态见文末。

## 用户日志能确认的事实

反馈环境是 Windows 26200 x64、Intel Wireless Bluetooth、驱动 20.100.5.1。最终会话使用增强模式并开启六轴，增强环境已就绪。

- 20:54:15 收到原按键首帧；20:54:16 切换 FD2 后收到有效六轴首帧。服务发现、游戏输出与体感初始化均曾成功。
- 20:54:23 电量刷新超时，旧日志称「已恢复公共输入」，但代码没有验证公共输入恢复，也没有区分超时发生在 Notify、首帧等待还是 None。
- 20:54:48–49 最终 `ObjectDisposedException` 的堆栈经过电量刷新。清理阶段的「对象已释放」警告发生在 finally，不能倒推为最初故障原因。
- 普通 Xbox 会话也出现稀疏/断流：125 份报告覆盖约两分钟，后一次重连读取服务超时。没有逐帧时间，不能说整段始终以 1 Hz 回报，也不能把所有问题归因于增强电量切换。

日志未包含适配器硬件型号 ID，无法据此指定替换驱动，更不能认定驱动是根因。本轮不修改系统驱动、配对资料、固件或系统蓝牙设置。

## 修改后的行为

### 固定输入通道，电量明确降级

移除 `RefreshPowerAsync` 及其周期任务。使用 FD2 时不再为了读取电量临时订阅互斥的原通道，从而消除刷新期间提前过滤 FD2、切换失败以及定时再次访问失效对象的路径。

最后可信电量仍可显示，但标注「上次读取」，不显示旧充电位的闪电。初始原报告未到达时显示未知，不把默认字节解释成 0%。正常使用原报告的两种模式继续实时显示电量和充电。

### 生命周期与未完成请求

每次物理连接有独立的取消令牌、报告来源与统计。蓝牙断开、GATT 会话结束、已关闭对象或休眠会终止该会话的运行等待；注销事件后，迟到回调也只能命中已结束的旧会话。

服务发现、通知配置和控制指令通过每连接独立的串行通道创建。超时或取消后，该通道停止接纳后续状态操作，不在未完成的 Notify 后立即发起 None。晚到结果仍被观察，晚到的服务/会话资源仍释放。重连前最多等待上一条请求及其迟到资源清理实际结束 8 秒，用户可取消；没有结束时不创建另一轮设备请求。旧请求已结束但报错，不把其异常转嫁给新连接。

这不表示软件能够强制终止 Windows 的底层连接过程。微软说明 GATT 请求可能排队、不可达请求可能逐项等待，连接过程不能直接取消；这里采用隔离、释放和等待可观察完成状态来控制应用行为。[微软 GATT 客户端说明](https://learn.microsoft.com/en-us/windows/apps/develop/devices-sensors/gatt-client)

### 受控恢复

超过 1 秒无有效输入时清空按键/摇杆输出、六轴角速度和震动。连续断流约 3 秒后，至多对当前输入通道尝试一次 None → Notify，并等待有效首帧最多 2 秒。每条配置请求有独立截止时间。

恢复前释放本应用持有的吞吐优先请求（如果存在），由系统决定后续连接参数；这不是驱动修复，也不保证改变实际无线参数。通知 ACK 不等于恢复成功；只有选中通道的新有效输入会确认成功。恢复失败或恢复后再次持续断流时结束当前连接，显示重试入口，避免无限停在「等待输入」。同一只虚拟手柄在成功恢复期间保留，不切换游戏模式。

清理优先停止游戏输入和震动。链路已失效或配置请求状态未知时，不继续对该 GATT 对象追加清理写入。已知仍可用的用户主动断开，则在有界清理预算内关闭体感并恢复默认报告。

## 软件回归

本轮已通过 **405 项核心检查**、**32 项真实 WinUI 检查**。新增核心覆盖 49 项；WinUI 新增电量快照、未知电量及断流后的状态/操作检查。构建以警告作为错误检查。

| 专项 | 验证内容 |
| --- | --- |
| Notify 超时/迟到完成 | 请求取消但原任务不结束；None 和后续配置均不启动；迟到成功也不重新开放旧通道 |
| None 恢复超时 | 不启动后续 Notify，不记录恢复成功，旧输入回调无法复活已结束会话 |
| 取消/失联 | 操作开始前、None 与 Notify 之间、Notify 过程中、等待首帧时取消；不启动下一阶段请求 |
| 对象已释放 | 保留原始异常，关闭会话，向用户解释需要重连，不只暴露英文异常 |
| 原生/FD2 输入所有权 | 只转发选中来源；未选中的原报告不能屏蔽持续 FD2 输入；旧会话不修改重连计数 |
| 恢复确认 | 只有 ACK、错误通道帧均不能证明成功；有效首帧在 Notify 返回前到达也能正确确认 |
| 跨连接隔离 | 等待旧请求及迟到资源清理真正结束；等待可取消/超时；旧错误不污染新连接；晚到资源只释放一次 |
| 断流策略 | 首帧超时、短暂中断、一次恢复、再次中断结束；结束时冻结输入年龄并记录末次断流间隔 |
| 界面/诊断 | 快照不显示旧充电状态；未知电量显示「—」；等待输入不显示就绪或伪造 Hz；失败后提供重试，保留脱敏诊断 |

可复现命令：

```powershell
./.tools/dotnet/dotnet.exe run --project tests/NS2Pro.Core.Tests -c Release -r win-x64
./.tools/dotnet/dotnet.exe build src/NS2Pro.App -c Release -r win-x64 -warnaserror
./scripts/test-ui.ps1 -OutputDirectory artifacts/checks/bluetooth-stability-ui
```

核心测试用可控任务模拟异常与迟到完成；WinUI 检查运行真实界面但隔离真实连接。它们不能证明旧 Intel 驱动或真实无线时序已经修复。
