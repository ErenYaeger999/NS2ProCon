# v0.8.5 修复与验证

本页记录 v0.8.5 的改进及验证边界，v0.8.4 及更早安装包不包含本轮新增内容。

## 产品与连接流程

连接按钮从环境检查开始进入「正在准备／取消连接」，增强环境仅准备一次。取消后不再进入扫描、创建输出或自动回退。增强临时不可用时，本次采用通用兼容，用户原来的增强选择继续保留；游戏运行中不自动更换输出。首页「更换手柄」清除记住的 PC 地址并重新等待 SYNC，不修改 NS2 配对。

原生设备、GATT 会话和服务读取增加独立截止时间与取消请求；取消后迟到的设备／服务结果会释放。通用驱动安装期间阻止退出与重复连接，需要重启时保存状态，避免反复运行安装器。指南与映射使用当前模式的说明，清理旧 HOME 警告。诊断增加模式、后端状态、适配器信息与时序，默认隐藏用户目录和完整手柄地址；驱动属性未能从 Windows 读取时明确显示未返回。

安装器阻止旧版本覆盖新版。正式打包要求已提交且干净的源码，清单记录提交号并核对 EXE 内的版本信息；开发验证可使用 `-SkipPackaging`，清单会标明未提交状态。不会重写已发布的 0.8.4 附件。

## 回报率与延迟

**回报率**是应用每秒实际收到多少份蓝牙输入报告，与游戏帧率、震动频率、虚拟设备定时刷新频率不同。显示值采用最近两秒的到达时间计算。约 66.7 Hz 对应平均 15 ms 报告间隔，不等于已经测到 15 ms 的按键到屏幕延迟。

程序在支持的 Windows 11 上已请求 `ThroughputOptimized`。它属于系统连接参数偏好，不能保证强制使用特定的连接间隔。[Microsoft 文档](https://learn.microsoft.com/en-us/uwp/api/windows.devices.bluetooth.bluetoothlepreferredconnectionparameters)还提示其可能增加功耗并减少同时连接设备的数量。同类 Windows BLE 项目的[已测限制](https://github.com/ZX8592/Switch2ProWirelessViiper#known-limitations)也是约 15 ms／67 Hz；[Switch2Connect](https://github.com/TommyWabg/Switch2Connect)区分了 Windows 原生 BLE、USB 和外置 ESP32 桥接的回报率。这些路径不能混作同一种连接方式的性能承诺。

本版不添加 125／250 Hz 选择器，也不通过更快重复提交旧数据来增加显示数值。更高回报率是否需要 USB、有特定固件的外置桥接或其他蓝牙栈，属于独立硬件路线，暂不增加默认依赖。

**本机转发耗时**从进入应用输入回调开始，到 Xbox 驱动调用返回，或 DualSense 本机 TCP 写入完成为止，包含解码和本机排队。界面显示最近两秒的中位数，诊断另含 P95。它不包含实体按键扫描、无线传输、游戏轮询、渲染及显示；不是端到端延迟。后者需要同步外部基准、摄像／电子测量等手段，当前没有用软件计时冒充测量。没有有效样本时显示「—」，断开后清除旧样本。

## 增强震动

此前分析所得 Hz 直接写入任天堂协议控制字段，没有经过标定的转换依据。现改为保留各侧低／高频带能量，采用 [SDL 的兼容载波控制码](https://github.com/libsdl-org/SDL/blob/main/src/joystick/hidapi/SDL_hidapi_switch2.c)，与有界强度及停止调度结合；不会把数值上相同的 Hz 和协议码视为等价。[上游编码说明](https://github.com/hbashton/DS4Windows/blob/main/DS4Windows/DS4Control/Switch2/Switch2HdRumbleCodec.cs)同样区分原始控制码与物理解释。

这消除了无依据的频率直传，但不代表完成原生 HD 震动复现。后续仍需做实际载波标定、轻微反馈、瞬态、持续效果和游戏对照；游戏同名也不保证 PC 与 NS2 版提供相同反馈。本文只引用协议事实与来源，未移植 GPL 算法代码。

## 增强后端边界

自动管理继续仅监听本机 IPv4，新增固定版本 [VIIPER auth-v2](https://github.com/hbashton/VIIPER/tree/v0.1.9-rc4.6.6/internal/server/api/auth)握手和认证加密记录；拒绝认证失败、错误方向、重放计数、篡改和过大记录，不自动降级明文。另核对 API／USB 监听端口属于应用启动的进程。

每次后端启动生成独立随机密钥；私有目录仅向当前用户和 SYSTEM 授权，密钥不写入诊断或日志。Windows 自带 ChaCha20Poly1305 在旧系统上[存在平台限制](https://learn.microsoft.com/en-us/dotnet/standard/security/cross-platform-cryptography)，使用 MIT 的 [NaCl.Core 2.2.0](https://github.com/daviddesmet/NaCl.Core)作为托管兼容实现，并交叉检查输出，不引入新驱动或原生加密 DLL。

手动后端由其原软件配置和管理，本应用不读取其密钥文件。USBIP 原生设备通道仍遵循上游驱动协议；本机绑定、端口归属和 API 认证不等于为 USBIP 增加了独立鉴权，也不防御已经能读取当前用户密钥或注入当前进程的程序。

### 本机实物复测 · 2026-10-18

用户完成取消等待、重新连接，以及增强／通用两种模式下的按键、摇杆和震动检查，反馈其余功能均正常，无音频切换或异常震动。增强模式约 **67 Hz／7–8 ms**，通用模式约 **66 Hz／0.1–0.2 ms**。后一个数值均指本机转发耗时，不是无线总延迟；增强路径包含定时发送调度，不能用其虚拟刷新频率冒充实体回报率。这是当前机器的记录，不能当作所有适配器或游戏的性能保证。

会话日志另记录：增强一段为中位 7.56 ms／P95 14.39 ms／118 样本，通用一段为中位 0.09 ms／P95 0.20 ms／130 样本，均取断开前最近两秒；两段平均实体输入均约 66.1 Hz。增强另一次重连为中位 7.80 ms／P95 14.47 ms。连接和震动清理完成，没有把这些结果记为端到端延迟。
