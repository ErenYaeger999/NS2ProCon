# 原生触觉增强 · 0.8.1

默认的通用兼容模式继续使用 ViGEmBus 和 Xbox 360 / XInput，无需以下组件。增强模式只适用于 PC 版本本身支持 DualSense 原生触觉的游戏，不能恢复游戏未输出的效果，也不能实现机械自适应扳机阻力。

## 使用流程

1. 断开 PC 手柄连接，在「设置与诊断 → 游戏模式」选择「原生触觉增强（实验）」。
2. 应用先检查环境；已有组件直接复用，只有确认缺少时才显示安装按钮及对应下载大小。仅缺触觉后端约 4 MB，缺驱动约 33 MB，两者都缺约 37 MB。安装驱动需确认 Windows 管理员弹窗，驱动可能短暂重连 USB 设备，请先完成文件传输。
3. 驱动安装后保存工作并自行重启电脑；应用不会强制重启。重新打开应用、进入游戏模式后会继续检测，也可点「重新检测」。
4. 显示「增强环境已就绪」后连接手柄。启动游戏前，检查 Windows「设置 → 系统 → 声音」：若输入／输出被切换成 DualSense，手动选回自己的麦克风和扬声器／耳机，确认声音与音量正常后再进入游戏；已经启动的游戏必要时退出重进。默认音频设备的保留与恢复尚待实现。部分游戏需要在 Steam 游戏属性中关闭该游戏的 Steam Input。

以后使用增强模式时，由应用启动和管理自己的后端，无需另开控制台。后端自身可能显示上游提供的托盘图标。选择结果会保留；只有环境验证成功才启用 DualSense 输出。下载取消、安装失败或等待重启时，可点「使用通用模式」继续普通游戏震动。

连接期间不能切换模式或重新检测，避免游戏运行中突然更换设备。状态「增强模式已连接，等待游戏反馈」不代表游戏不支持；收到非零原生触觉采样后才显示「正在接收游戏原生触觉」。不会根据暂时没有震动自动切换设备。

## 管理范围和检查

应用目录：`%LOCALAPPDATA%\NS2Pro\Enhancement`，含已校验下载缓存、固定版本后端及其许可证、独立配置和重启标记。普通设置继续位于 `%LOCALAPPDATA%\NS2Pro\settings.json`。

后端只监听 `127.0.0.1:32451`（USB）和 `127.0.0.1:32452`（API），使用专属配置和密钥文件，不读取 `%APPDATA%\VIIPER`。清除子进程继承的 `VIIPER_*` 覆盖变量，不调用上游安装／开机启动脚本。端口被占用时停止并提示，不连接占用者冒充的后端。

后端进程通过本应用的 Job Object 管理；退出、取消启动、启动失败或切回通用模式时只结束本应用启动的进程。已有 VIIPER / DS4Windows 运行而驱动需要变更时，要求先退出原软件，不按进程名强制结束它。普通断开只释放自己创建的虚拟手柄，保留后端以便下次连接。

就绪检查依次覆盖固定文件哈希、驱动 CLI 版本与实时 `port` 检查、后端身份、自己新建的虚拟 DualSense HID，以及相同设备容器中的音频输出端点。自检结束移除自己新建的总线，不保留额外游戏手柄，不改变默认声音设备。游戏会话同一时间只输出一种虚拟手柄。

高级选项「自动管理增强后端（推荐）」开启时，由本应用检查、启动并管理后端；关闭时，才连接其他软件已运行的 VPCM V5 后端，并显示端口设置。手动模式不会启动本应用已下载的后端。若提示外部后端未启动，点击「改用自动管理并检测」会开启自动管理，再检查已有组件；齐全时直接启动并验证，缺少时才提供单独的安装按钮。切换方式、修改端口和重新检测都不会下载或安装；修改端口后清除旧的就绪状态，需要重新检测。升级前已配置的外部后端保持外部管理，不接管其生命周期。既有配置需要允许本机 API；应用不会读取其他软件的密码。

检测失败、取消或等待重启时，主操作为「重新检测」，不再把检测失败统称为「重试安装」。驱动已登记安装但不可用时，展示检查错误，避免反复运行安装器；只有未安装的驱动才提供安装步骤。无需为每次环境检测重启电脑，仅驱动安装完成后提示重启。

## 来源与验证边界

VIIPER 为 GPL-3.0-or-later，下载部署保留包中全部许可证、构建信息和来源入口；USBIP 使用其上游各组件许可证。本仓库未加入第三方二进制，应用通过独立 IPC 实现连接。未来若镜像或捆绑分发二进制，应另行履行对应源码、许可和通知要求，不能仅以分进程为依据推断许可豁免。

自动检查覆盖设置迁移、固定版本、缓存、下载取消／截断／超长／哈希损坏、压缩包路径与许可证完整性，并保留已有 V5 协议及通用震动检查。实际 WinUI 页面另行检查状态和操作约束。驱动安装、重启后的真实虚拟音频通道及游戏触觉链路必须实机验证后再记为通过；进程启动或模拟服务器通过都不能替代该验证。

## 本机环境验证 · 2026-10-17

已安装并重启后的 USBIP CLI 返回 0.9.7.7，实时端口检查通过。使用本应用的进程管理、专用配置和端口启动固定版 VIIPER 后，实际创建了虚拟 DualSense（VID 054C / PID 0CE6），检测到同设备容器内的音频输出端点；自检结束移除自己的总线并结束自己的后端进程。此项验证未连接实物手柄，也未改变默认声音设备，不能替代真实游戏的原生触觉实测。

此前反复“未找到本地 VIIPER”的会话处于外部后端管理模式；驱动安装和重启不会启动外部管理的后端。现已增加准确提示和「改用自动管理」入口。首页、首次指南和托盘连接统一走同一入口：未准备好的增强选择不阻止默认通用兼容连接；已启用的增强若在连接前检测失败，显示说明并回退通用模式。游戏运行中不自动更换虚拟设备。
