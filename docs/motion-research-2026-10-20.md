# NS2 Pro DualSense 体感集成调研

调研日期：2026-10-20。代码基线：本项目 v0.8.6（`05eecb0`）。用户优先需求：转动手柄微调视角／准星。

调研阶段核对了本项目代码、上游协议文档及具体实现。随后用户明确选择：**只开发 DualSense 六轴透传，不开发体感转鼠标或摇杆**。当前已接入本地候选代码，实物与游戏验证记录另列于[使用说明](motion.md)。

## 结论

可以集成，有可参考的开源实现。实现范围为物理传感器读取、静置校准、坐标与单位转换，再通过现有 DualSense 输出交给游戏／Steam。

- **真实六轴透传：复用现有 DualSense 增强输出。** 本项目固定的 VIIPER 版本已经支持六轴字段。协议层面无需更新增强后端；游戏或 Steam 的识别、时间轴和实际手感仍需验证。
- **校准和检测留在连接器，瞄准设置交给游戏／Steam。** 不新增本应用的瞄准键、灵敏度、游戏配置或鼠标映射。
- 普通 Xbox 模式不初始化传感器。不新增第二只虚拟手柄，不在游戏运行中自动切换输出设备。

XInput 的手柄状态没有陀螺仪／加速度字段，因此普通 Xbox 模式不提供原生六轴。[微软 XINPUT_GAMEPAD 定义](https://learn.microsoft.com/en-us/windows/win32/api/xinput/ns-xinput-xinput_gamepad)

## 可用路径与取舍

| 路径 | 游戏中的用法 | 与现有输出的关系 | 主要限制 | 建议 |
| --- | --- | --- | --- | --- |
| 六轴 → 虚拟 DualSense → 游戏原生体感 | 在游戏里开启陀螺仪 | 复用增强模式同一只虚拟设备 | PC 版需实际支持体感，不是支持 DualSense 震动就一定支持体感 | 作为原生透传入口 |
| 六轴 → 虚拟 DualSense → Steam Input | 在 Steam 的控制器布局中设置体感 | 复用增强模式，但 Steam 可能再转换成 Xbox／鼠标 | 需逐游戏核对原生触觉是否保留 | 可选高级用法 |
| DSU／Cemuhook | 供明确支持该协议的客户端读取 | 独立本机数据出口 | 不是通用 PC 游戏接口，主要用于特定客户端 | 本次不做 |

Steam 后续如何映射六轴由用户的 Steam 配置决定。其官方说明体感转鼠标仍依赖游戏接受混合输入，不能把透传成功等同于所有游戏体感可用。[Steam Input 最佳实践](https://partner.steamgames.com/doc/features/steam_controller/steam_input_gamepad_emulation_bestpractices?language=english)

### 与增强震动的关系

传感器读取与蓝牙震动写入可以在架构上分开调度。真正需要核对的是游戏如何使用输出设备：

- 交给游戏原生处理六轴时，是否同时支持触觉取决于 PC 版实现。
- 交给 Steam 映射时，不能默认承诺游戏仍获得原生 DualSense 设备和触觉音频。hbashton 的 DS4Windows 明确建议原生 DualSense 反馈场景关闭重叠的 Steam Input 映射。[上游说明](https://github.com/hbashton/DS4Windows#readme)
- 不在连接器里按 ZL 门控原始传感器；启用条件、灵敏度、玩家坐标投影均由游戏／Steam 决定。

## 物理读取：关键问题不只是添加几个字段

### 当前输入与已知原始格式不同

本应用 `ControllerService` 订阅 `7492866c-ec3e-4619-8258-32755ffcc0f8`，对应 Pro 专用报告 `0x09`；`ControllerProtocol.Decode` 只处理按钮、摇杆、电量。该报告的体感区在已核对文档里仍标注为未知打包格式，不能直接将后面的字节解释为连续六个 `int16`。

已知可用的替代通道是公共报告 `0x05`，特征 UUID 为 `ab7de9be-89fe-49ad-828f-118f09df7fd2`。BLE 数据不含 USB 的报告 ID 字节，以下偏移均以 BLE payload 为起点：

| 字段 | BLE 偏移 | 格式 |
| --- | --- | --- |
| 体感时间戳 | `0x2A` | `uint32`，文档标为微秒，但部分设备异常 |
| 温度 | `0x2E` | `int16` |
| 加速度 X／Y／Z | `0x30`／`0x32`／`0x34` | 小端有符号 `int16` |
| 陀螺仪 X／Y／Z | `0x36`／`0x38`／`0x3A` | 小端有符号 `int16` |

至少需要 60 字节才有完整六轴。这个位置也与 C# 参考项目从偏移 48 复制 12 字节原始六轴的实现一致。[报告定义](https://github.com/ndeadly/switch2_controller_research/blob/a3306b473acff0d6844fb1e288883a3940df0baf/hid_reports.md)、[C# FD2 解析器](https://github.com/ZX8592/Switch2ProWirelessViiper/blob/e3eb25f51a80870f51892b7457f5a0943a9e143a/Core/Fd2ReportParser.cs)

首轮实测中 IMU 启用应答成功、原 Pro 按键通知正常，但没有收到 FD2 通知。因此不能以 CCCD 或命令成功作为就绪依据。修复候选增加了真实首帧验证，必要时关闭 Pro 通知、切换公共报告，以 FD2 同时接收完整按键和六轴；电量与充电位仍从原 Pro 报告只读刷新。没有有效体感首帧则恢复 Pro 报告和通知，保留原有连接。

公共传输启动仅使用文档中的 `03/0A` 报告选择（05／09）及 `03/0D` 瞬时启动，使用无效主机地址占位；不调用配对的 `03/07`、`03/08`、`03/09` 或 `15/*`。这些启动条件仍需第二轮实物验证。

### 最小启用命令，保留已有状态

协议的 Feature Select `0x0C` 中，bit 2（`0x04`）是 IMU；设置允许掩码与启用功能是两步。按钮、摇杆、震动等是其他 bit，需要保留原有功能并只增加必要传感器状态。[命令定义](https://github.com/ndeadly/switch2_controller_research/blob/a3306b473acff0d6844fb1e288883a3940df0baf/commands.md#command-0x0c---feature-select)

C# 参考项目启用了整个 `0xFF` 掩码，并发送了一串初始化，其中包括配对相关的 `0x15/0x03`。本应用不应照搬整串命令：需要逐项验证最小瞬时启用序列，继续保持临时 SYNC 连接。新增流程不发送配对、写 Flash、固件更新或主机唤醒命令；软件校准存于 PC，不写回手柄。

### 单位、坐标与校准需要交叉验证

上游存在实际差异：协议文档列默认陀螺仪 ±2000 °/s；Switch2Connect 对 Pro 使用约 14.285714 LSB/(°/s)，对 Joy-Con 使用 16.384；SDL 则根据传感器时间戳特征选择不同角速度系数。不能把 Joy-Con 的系数直接当成所有 Pro 固件的标定。

验证方法：

1. 六个朝向静置，检查重力大小与加速度轴方向。
2. 分别绕三轴完成已知角度旋转，检查方向与积分角度；区分量程换算和用户灵敏度。
3. 静置采样计算零偏；校准期间有明显运动就延长／重试，不能把手部运动记为偏置。
4. 只读工厂数据作为候选校准来源。SDL 在 `0x13040` 区块读取三个浮点陀螺仪偏置，但必须验证数据有限性、适用单位与实物表现，再决定是否采用。
5. 先统一内部坐标与单位，再分别转换为鼠标轴或 DualSense 轴；不可直接把 Nintendo 原始整数复制进 DualSense 六轴字段。

源代码交叉核对：[SDL 校准与传感器处理](https://github.com/libsdl-org/SDL/blob/3b2bc951500ca6a1f428af77e036e732d9a8afe3/src/joystick/hidapi/SDL_hidapi_switch2.c)、[Switch2Connect 的单位定义](https://github.com/TommyWabg/Switch2Connect/blob/e5dd90bb54106b35a1110f96ec9d060390e5d096/src/gyro.py)。这些差异是需要实测的原因，不应在 UI 中要求用户选择原始量程。

第一阶段不依赖磁力计。磁场容易受桌面金属、电子设备等影响，增加磁力计校准不应成为开启瞄准的前置步骤。目标是相对角速度控制与稳定微调，先不承诺长期无漂移的绝对朝向。

## 现有 DualSense 输出的接入位置

本项目使用的 `dualsensecombinedaudioduplexv5` 已接收 33 字节基础输入。上游固定版本的布局为：

| 字段 | 输入 payload 偏移 | 规范单位 |
| --- | --- | --- |
| Gyro X／Y／Z | 21／23／25 | `int16`，16 单位/(°/s) |
| Accel X／Y／Z | 27／29／31 | `int16`，8192 单位/g |

v0.8.6 的 `DualSenseWire.Input` 只填写前 11 字节，六轴保持零值；本地候选版现已按同一协议填写规范六轴，不需要另建虚拟手柄。[固定版本协议](https://github.com/hbashton/VIIPER/blob/v0.1.9-rc4.6.6/docs/devices/dualsense.md)、[输入布局](https://github.com/hbashton/VIIPER/blob/b78e31e93e84b4cb7c4b4c15b8aace10749106d2/device/dualsense/state.go)

后端虚拟校准已经描述上述规范单位，不要再次套用物理 DualSense 工厂系数。静止时真实加速度包含重力，不能为“中立状态”把三个加速度全部置零。规范数据转 `int16` 时需饱和限制。

该 33 字节格式没有独立物理传感器时间戳。现有 8 ms 虚拟输出节拍和约 15 ms 的真实 BLE 数据节拍不同，需要实测 Steam／SDL 接收到的时间轴与积分结果；不能把后端用于物理 DualSense 元数据的扩展块直接塞入 NS2 数据。

VIIPER 也有虚拟 `ns2pro` 路径，但这是另一种输出身份及反馈协议。首版不增加第三种游戏模式；先复用已有 DualSense 路线，避免把读取体感与重做输出、震动一起扩大。

## 最小产品设计

保留现有「游戏模式」和「按键布局」含义，不增加第三种游戏模式。

- 增强设置下显示 **体感输入** 开关，默认开启，仅影响下一次 DualSense 连接；连接期间禁用修改，并解释需要先断开。
- 瞄准灵敏度、启用键、坐标投影由游戏／Steam 设置，连接器不重复提供。
- 「手柄测试」增加三轴速度指示、真实有效采样率、加速度大小及静置校准。指示表示转动速度，不冒充绝对姿态。
- 首次使用建议将手柄放稳约 2 秒校准。校准期间暂停震动；检测到运动重试静止窗口，数据中断则取消，保留上次零点。
- 普通模式的测试页解释 DualSense 前置条件，并提供设置入口；不会自动安装组件或切换虚拟设备。
- Steam 可能影响原生触觉的提示放在增强体感设置内，不做每次连接都要确认的弹窗。

## 建议接入顺序与验收

### A. 先验证读取，不改变游戏控制

1. 在可取消、可清理的现有 BLE 会话内探测 FD2；逐项验证最小传感器启用命令。
2. 增加独立 `MotionSample`，记录真实到达时间、可用的设备时间戳、序号、六轴及有效性。普通按钮报告不伪造运动样本。
3. 记录静止、单轴转动、快速转动、震动同时运行的短样本，核对单位与轴方向。
4. 确认原输入报告、ABXY／背键、摇杆校准、电量／充电、两种震动都保持正常；失败时体感单独停用，不阻断普通连接。

### B. 做静置校准与体感检测

1. 提供静置校准和运动检测，零偏按物理手柄标识保存在 PC。缓慢瞄准时不自动重设零点。
2. 规范单位透传，不在连接器积分准星角度、添加瞄准曲线或输出鼠标／摇杆。
3. 原始设备时间戳仅供诊断，使用本机单调时钟判断数据年龄，避免已知异常时间戳污染输出。
4. 断开、休眠及数据过期时清除角速度；校准不将重力归零。
5. 只保留最新状态；重连建立新会话，不补播上个连接的转动。UI 与传感器处理分别调度。

### C. 增加六轴透传并验证共存

1. 扩展游戏输出状态，保持按钮／摇杆／体感快照一致；Xbox 路径不受新增可选字段影响。
2. 按上述规范填写 V5 六轴，处理重复样本、缺失数据与有效期。后端周期提交不计为新的物理样本。
3. 先用 SDL／Steam 检查虚拟设备的角速度、加速度、时间轴，再验证支持原生体感的 PC 游戏。
4. 分别测试游戏原生体感、Steam 映射与增强震动组合，不将一种组合成功推广为所有游戏成功。

### 专项验证表

| 范围 | 必测项目 | 通过标准 |
| --- | --- | --- |
| 数据解析 | 短包、负值、极值、USB／BLE 偏移区别、序号回绕 | 不越界、不误读打包格式，不产生非有限数 |
| 时间轴 | 重复／倒退／零时间戳、32 位回绕、断流、重连 | 不除零、不积累巨量角度，不补发陈旧位移 |
| 校准 | 静置、有动作时校准、慢速跟踪、温度变化 | 动作不记为零偏；慢速瞄准不被自动校准吞掉 |
| 精度 | 三轴方向、已知角度旋转、重力大小、微小往返 | 方向正确，单位可追溯，低速动作连续，无明显长期拖尾 |
| 输入共存 | 双摇杆／ABXY／ZL／背键，同时体感和震动 | 原控制正常，不出现重复虚拟设备 |
| 游戏范围 | 菜单／地图／暂停、Alt-Tab、退出、窗口切换 | 原生体感由游戏或 Steam 控制，兼容说明与实际一致 |
| 增强输出 | 原生体感与触觉、Steam 转换开／关 | 分别记录有效组合；音频默认设备保护仍正常 |
| 主机使用 | 临时 SYNC、NS2 休眠、断开后 HOME 回主机 | 不改主机配对，仍无需重新配对 |
| 稳定与功耗 | 长时间运行、失联、休眠、重复开关体感 | 无后台持续输出，输入／震动无积压，记录新增耗电 |

六轴重力、轴变换、规范单位转换、序号回绕、过期样本、校准和重连清理适合自动检查。BLE 通道共存、真实漂移、Steam 识别和游戏手感必须实物验证。

## 回报率与延迟

现有约 66–67 Hz 是本机收到输入通知的频率，不能直接等同于 IMU 内部采样率。接入后分别统计物理体感有效样本率、样本间隔与数据年龄。固定格式 FD2 当前可解析一组六轴；未知打包报告里是否包含更多样本，需要独立证据。

SDL 注册的 250 Hz 传感器能力不能当成当前 Windows BLE 链路已达到 250 Hz。将鼠标或虚拟报告按 500／1000 Hz 更新，也不会创造同样数量的新测量。首版优先解决正确、均匀、低漂移与及时停止，不添加无硬件依据的高回报率选择框。

内部转发耗时、收到样本后的数据年龄可以测；转动手柄到屏幕准星响应的完整延迟仍需要外部测量。不要用当前「本机转发耗时」代替体感端到端延迟。
